# Bug Report Template

Copy this for every defect. Delete fields that genuinely don't apply — but delete them
deliberately, not by forgetting.

**Non-negotiable core:** Title · Steps · Expected · Actual · Severity · Priority ·
Environment · Reproducibility · Evidence.

---

```
ID:                 (auto-generated by the tracker)

TITLE:              [Area]: <what goes wrong> when <condition> (<scope>)
                    e.g. Checkout: order total excludes VAT when a coupon is applied

DESCRIPTION:        1–3 sentences. What is wrong, who it affects, and why it matters.
                    Include frequency/reach if you know it ("~18% of orders").

PRECONDITIONS:      The state required before step 1. Must be verifiable.
                    e.g. Account X exists, is ACTIVE, has 0 previous orders;
                         coupon SAVE20 is active and unused by this account.

TEST DATA:          Exact accounts, values, records, SKUs.
                    e.g. qa.efe+coupon01@example.com / ValidPass!456; SKU BK-1099; coupon SAVE20

STEPS TO REPRODUCE:
                    1. <one action per step, exact values>
                    2. ...
                    3. ...   ← FAILS HERE
                    (Minimise these. Shortest sequence that still fails.)
                    Note any order dependency: "must apply the coupon BEFORE selecting delivery"

EXPECTED RESULT:    What should happen, and WHY you believe that.
                    Source: REQ-88 / story PAY-3990 AC3 / design mock-up v4

ACTUAL RESULT:      Exactly what happened. Values, messages, status codes.
                    Include the downstream consequence if there is one
                    (e.g. "the invoice PDF also omits VAT").

SEVERITY:           Blocker | Critical | Major | Minor | Trivial
                    Justification: <one line>

PRIORITY:           P1 | P2 | P3 | P4   (proposed — triage confirms)
                    Justification: <reach × cost, workaround, deadline>

ENVIRONMENT:        Environment:  QA2 (https://qa2.example.com)
                    Build:        4.3.0-rc2 (commit a1b2c3d, deployed 2026-03-12 09:10 WAT)
                    Browser/OS:   Chrome 121.0 / Windows 11, 1920x1080
                    Account role: Standard customer (not admin)
                    Feature flags: new_pricing_engine = ON
                    Also reproduced on: <other browsers/devices/environments>
                    NOT reproduced on: PROD 4.2.9  →  REGRESSION in 4.3.0

REPRODUCIBILITY:    Always (10/10) | Intermittent (3/10) | Once
                    Pattern noticed: <e.g. only on first attempt after fresh login>

MODULE/COMPONENT:   Checkout / Pricing engine

WORKAROUND:         What users or support can do meanwhile. "None" is a valid — and important — answer.

IMPACT:             Who is affected and how many. Quantify where you can.

EVIDENCE:           [ ] Screenshot (annotated)
                    [ ] Screen recording (< 60s) — for intermittent or timing bugs
                    [ ] Browser console output (as text, not a picture of text)
                    [ ] HAR file — SECRETS SCRUBBED
                    [ ] Request/response (method, URL, headers, body, status)
                    [ ] X-Request-Id / correlation ID: ____________
```

## Pre-submit checklist

- [ ] Reproduced it **at least twice**
- [ ] **Minimised** the steps
- [ ] **Searched for a duplicate**
- [ ] Title is self-explanatory in a list of 200
- [ ] A stranger could follow the steps with no verbal explanation
- [ ] Exact test data and account are in the ticket
- [ ] Expected vs actual are separate, and expected has a **source**
- [ ] Environment **and build number** recorded
- [ ] Checked whether it also happens on the **previous build / production** (regression?)
- [ ] Evidence attached, **secrets redacted**
- [ ] Frequency and affected-user count stated
- [ ] Workaround stated (or explicitly "none")
- [ ] Severity and priority **justified**, not just asserted
- [ ] **One** defect in this ticket, not several

---

## Severity reference

| Severity | Definition |
|---|---|
| **Blocker** | Testing cannot continue; system unusable |
| **Critical** | Major function broken, data loss/corruption, financial or security impact, no workaround |
| **Major** | Important function broken or badly wrong, workaround exists |
| **Minor** | Small functional problem, low impact |
| **Trivial** | Cosmetic only |

## Priority reference

| Priority | Meaning |
|---|---|
| **P1** | Drop other work; fix now, possibly hotfix |
| **P2** | Must be fixed before this release ships |
| **P3** | Should be fixed in a coming sprint |
| **P4** | Fix when convenient; may never be fixed |

**Severity = technical impact (tester decides). Priority = business urgency (PO decides).**
